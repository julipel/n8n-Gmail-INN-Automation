# n8n Gmail INN Automation (AI)

Автоматизация в `n8n` для обработки входящих заявок в Gmail: организации и их ИНН извлекаются из письма **через LLM** (а не регулярками), после чего идёт проверка дубля по ИНН в Google Sheets и автоответ клиенту (с вложением, если проект новый).

## Что делает workflow

1. Отслеживает входящие письма Gmail по фильтру темы (`SUBJECT_FILTER_QUERY`), исключая собственные (`-from:me`).
2. Получает письмо целиком (`Gmail Get Message`) и готовит для LLM только метаданные + текст письма (`Prepare Email Data`) — без regex-парсинга полей.
3. **AI Extract Organizations** (`@n8n/n8n-nodes-langchain.informationExtractor`, модель `gpt-4o-mini` через `OpenAI Chat Model`) вытаскивает из письма список организаций (`org_name`, `inn`, `org_address`) по строгой JSON-схеме и системному промпту. Поддерживает произвольный формат: обычный текст, список, таблицу, вставку из Excel/Sheets, несколько организаций в одном письме.
4. **Validate Organizations** нормализует и валидирует результат LLM:
   - ИНН должен быть 10 или 12 цифр, иначе организация отбрасывается с записью в `warnings`;
   - организации без `org_name` отбрасываются;
   - дубли ИНН внутри одного письма схлопываются;
   - если ни одной валидной организации не осталось (или LLM вернула ошибку/невалидную структуру) — письмо помечается `needs_manual_review: true`.
5. **IF - Needs Manual Review?**:
   - **true** → `Needs Manual Review` — письмо и причина проблемы упаковываются для ручной проверки, без записи в Sheets и без автоответа.
   - **false** → `Split Organizations` — каждая организация превращается в отдельный item и обрабатывается независимо дальше по цепочке.
6. Для каждой организации: поиск в Google Sheets по `inn`, сверка результата (`Code - Check INN Exists`) и ветвление по `inn_exists`:
   - **ИНН уже есть** → письмо с указанием ИНН (и названия организации, если распознано), без вложения.
   - **ИНН новый** → строка добавляется в Google Sheets → скачивается файл коммерческого предложения из Google Drive → отправляется письмо с ИНН/названием и вложением.

## Стек

- `n8n` (self-hosted / cloud)
- `Gmail Trigger` + `Gmail` (получение писем и отправка ответов)
- `@n8n/n8n-nodes-langchain.informationExtractor` + `OpenAI Chat Model` (`gpt-4o-mini`) — извлечение организаций из текста письма
- `Google Sheets` (реестр проектов, поиск по ИНН)
- `Google Drive` (шаблон коммерческого предложения для вложения)
- `Code` nodes (чистый JavaScript, без внешних библиотек)

---

## Структура workflow

```
Gmail Trigger
  → Gmail Get Message
  → Prepare Email Data
  → AI Extract Organizations  ←  OpenAI Chat Model (gpt-4o-mini)
  → Validate Organizations
  → IF - Needs Manual Review?
      TRUE  → Needs Manual Review                 (конец, без Sheets/автоответа)
      FALSE → Split Organizations                  (1 item на организацию)
              → Google Sheets - Read All Rows       (поиск по inn)
              → Code - Check INN Exists
              → IF - INN Exists?
                  TRUE  → Gmail Send - Duplicate INN
                  FALSE → Google Sheets - Append Row
                          → Download file (Google Drive)
                          → Gmail Send - Success With Attachment
```

## Требуемые credentials

Создать в n8n:

- `Gmail OAuth2` — для чтения и отправки писем
- `Google Sheets OAuth2` — для чтения/записи реестра проектов
- `Google Drive OAuth2` — для скачивания файла КП, который прикладывается к ответу
- `OpenAI API` — для `OpenAI Chat Model` (извлечение организаций из письма)

## Placeholders (обязательные для замены)

| Placeholder | Где используется | Что подставить |
|---|---|---|
| `SUBJECT_FILTER_QUERY` | `Gmail Trigger` | текст темы письма, по которому фильтруются заявки |
| `GOOGLE_SHEET_ID` | `Google Sheets - Read All Rows`, `Google Sheets - Append Row` | ID таблицы-реестра |
| `SHEET_NAME_MAIN` | те же ноды | имя листа (например, `Sheet1`) |
| `GOOGLE_DRIVE_FILE_ID` | `Download file` | ID файла КП на Google Drive, который прикладывается к успешному ответу |

## Формат таблицы Google Sheets

На листе должна быть строка заголовков:

- `created_at`
- `sender_email`
- `inn`
- `org_name`
- `org_address`
- `message_date`
- `subject`
- `message_id`

Столбец `inn` используется как ключ поиска (`Google Sheets - Read All Rows` фильтрует строки по `inn = {{$json.inn}}`).

## Извлечение данных из письма (AI)

В отличие от regex-версии, парсинг не завязан на фиксированный формат `Название: / ИНН: / Адрес:`. LLM работает по системному промпту (см. `AI Extract Organizations` в JSON) и возвращает строго типизированный JSON:

```json
{
  "organizations": [
    { "org_name": "ООО \"Ромашка\"", "inn": "7712345678", "org_address": "г. Москва, ул. Примерная, д. 1" }
  ],
  "warnings": []
}
```

Ключевые правила промпта:

- одно письмо может содержать одну или несколько организаций (обычный текст, список, таблица, вставка из Excel/Sheets — формат не важен);
- ИНН — только цифры, длина строго 10 или 12;
- телефоны, даты, номера договоров, КПП, ОГРН не должны приниматься за ИНН;
- подпись отправителя, телефон, email не должны попадать в название/адрес организации;
- если LLM не уверена в привязке ИНН к организации — это уходит в `warnings`, а не додумывается;
- организация без валидного ИНН не попадает в основной массив.

`Validate Organizations` — это дополнительный слой валидации поверх ответа LLM (код-нода), который не доверяет модели вслепую: сам проверяет длину ИНН, непустоту названия и уникальность ИНН в письме.

## Ручная проверка (Needs Manual Review)

Если LLM вернула ошибку, невалидную структуру, либо после валидации не осталось ни одной организации с корректным ИНН — письмо не идёт дальше в Sheets/автоответ, а попадает в ветку `Needs Manual Review` с полями `error_reason` и `warnings`. В этой ветке нет записи в Google Sheets и нет отправки письма — она рассчитана на то, чтобы эту ветку дополнительно подключить к своему процессу ручной проверки (например, уведомление в Slack/Telegram или отдельная таблица).

## Текст ответных писем

Оба автоответа подставляют ИНН и (если распознано) название организации:

- Дубль: `Добрый день! Проект с ИНН {{$json.inn}} ({{$json.org_name}}) уже принят в работу.`
- Новый проект: `Добрый день! Проект с ИНН {{$json.inn}} ({{$json.org_name}}) принят в работу. Прикрепляю коммерческое предложение.`

Если `org_name` не распознан, название в скобках просто не добавляется.

## Важные замечания

### Множественные организации в одном письме
`Split Organizations` превращает одно письмо в несколько items — по одному на каждую организацию, извлечённую LLM. `Code - Check INN Exists` сопоставляет каждую организацию с результатами поиска в Sheets по `pairedItem`, с фолбэком на полный набор строк (на случай, если сопоставление по индексу недоступно).

### Тип `inn_exists` / `needs_manual_review`
Обе код-ноды возвращают строго boolean для этих полей — это важно для корректной работы IF-нод со strict type validation.

### `alwaysOutputData` на `Google Sheets - Read All Rows`
Включено намеренно: если по ИНН ничего не найдено, нода всё равно должна вернуть пустой item, иначе для организаций без совпадений в таблице обработка молча остановится.

### Стоимость и задержка
Каждое входящее письмо — это один вызов `gpt-4o-mini`. Для писем, не проходящих фильтр темы (`SUBJECT_FILTER_QUERY`), вызова не происходит — фильтрация на уровне Gmail-запроса, а не после.

## Запуск self-hosted (docker compose)

```bash
docker compose -p n8nlocal up -d
```

См. `docker-compose.yml` в репозитории — поднимает `n8n` на `localhost:5678` с таймзоной `Europe/Moscow`. Перед запуском замените `N8N_ENCRYPTION_KEY` на собственное значение (минимум 32 символа).

## Импорт workflow

1. В UI n8n: `Workflows` → `Import from file`.
2. Выбрать `Gmail INN Automation AI.json`.
3. Подключить credentials (Gmail OAuth2, Google Sheets OAuth2, Google Drive OAuth2, OpenAI API).
4. Заменить все placeholders (см. таблицу выше).
5. Проверить соответствие заголовков в Google Sheets ожидаемой схеме.
6. `Activate`.

## Тест-план

1. Письмо с новым ИНН (обычный текст):
   - LLM корректно извлекает org_name/inn/org_address;
   - строка добавляется в Google Sheets;
   - приходит письмо с указанием ИНН/названия и вложением КП.
2. Письмо с уже существующим в таблице ИНН:
   - новая строка не добавляется;
   - приходит письмо с указанием ИНН/названия, без вложения.
3. Письмо с несколькими организациями сразу (в т.ч. в виде таблицы):
   - каждая организация обрабатывается независимо (своя проверка на дубль, свой ответ/запись).
4. Письмо без ИНН или с "мусорными" числами (телефон, номер договора):
   - организация с этим номером не должна попасть в `organizations` как валидная — либо число не распознаётся как ИНН, либо письмо уходит в `Needs Manual Review`.
5. Письмо, не подходящее под `SUBJECT_FILTER_QUERY`, или отправленное с собственного адреса — не должно триггерить workflow (`-from:me`, `in:inbox`), соответственно без затрат на LLM.

## Безопасность

- Не хранить OAuth/API токены, ID таблиц/файлов и реальные фильтры тем писем в репозитории — использовать placeholders.
- Не коммитить `.env` и любые файлы с реальными credentials.
- Публикуемая версия `Gmail INN Automation AI.json` в этом репозитории уже очищена от реальных ID и имён credentials — перед импортом в свой n8n подставьте собственные значения.
- Помните, что текст письма отправляется во внешний LLM-провайдер (OpenAI) — учитывайте это, если в письмах может быть чувствительная информация.
